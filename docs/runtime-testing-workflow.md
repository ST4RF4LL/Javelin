# 静态审计与独立动态测试

## 基于最终报告补充动态验证

在新版工作台进入“审计报告 → 查看报告 → 基于报告验证”，填写授权测试环境、登录方式与测试范围，选择动作和总预算后创建任务。来源报告所属产品固定；读取报告或打开表单不会启动 Agent、浏览器或目标请求。报告本身不授予动态执行权限。

该入口适用于前一轮环境接触超时、动态未执行或希望用最终漏洞清单定向复验的场景。它创建独立的 `runtime-testing.v2` 任务，使用 `TARGETED_CONFIRMATION`，不重跑静态审计，不启动自主探索 Planner。必要的环境登记与登录最多 120 秒，随后按报告清单逐项 CONFIRM，每项最多 300 秒，仍受用户总预算与清理预留预算约束。环境准备受阻时停止目标操作，逐项记录未执行原因；不会用提高原任务超时或反复探索来消耗整个预算。

支持带结构化模型的 task-board v1/v2/v3 最终报告，以及可通过原契约校验的历史最终报告；来源 Markdown 必须与模型重新渲染一致。提取已确认漏洞和未确定候选，排除已裁定的误报。创建时检查产品归属、来源任务活动状态、报告与模型摘要，冻结候选快照；来源版本变化须重新打开表单。当前最多 500 项，每项上下文最多 6.4 万字符，候选总上下文最多 2M 字符，超限明确拒绝，不静默截断。

新任务有独立预算与结果文件，保留来源审计、报告及模型 SHA-256、原漏洞标识、每项执行状态、观察结果、独立复核和清理记录。Worker 接收该项完整复现线索和私有环境原文；支持证据仍进入现有独立三方复核。原报告和原结论不改写，未复现不代表安全；部署与源码映射未验证时仍保持 UNKNOWN。原环境的隔离或待人工检查租约仍有效，新入口不会自动清锁。

离线回归：`npm --prefix .opencode run test:report-validation`。用例使用假 Worker、假浏览器及测试自身的 loopback API，不连接业务环境或调用真实模型。

## 三种任务模式（runtime-testing.v2）

本轮按会话 `01a13adf-736d-7690-8ccb-08c3d8148cc2` 中的静态／动态协作方案实现，复用本平台的执行、证据和复核机制；未复制 ARTEX 的实现或引入容器。

| 模式 | 创建条件 | 处理流程 |
| --- | --- | --- |
| 静态审计 | 一个本机源码对象 | 原 Focus Area、逐 API 或逐文件策略；不启动动态分支 |
| 独立动态测试 | 产品、显式授权与完整环境说明 | 无需源码和已有漏洞；环境接触、实际入口观察、有界实验、独立复核、报告存档 |
| 静态＋动态联合 | 源码对象，可选授权环境 | 静态与动态并行，双向交接线索，汇合后统一复核；没有环境时动态记为 SKIPPED，静态继续 |

Web 和原生 Agent 入口都接受 `audit_mode=static|dynamic|joint`。Web 任务由后台创建执行会话；原生入口保留当前主会话。任务和子工作进程沿用已选的 OpenCode v1、OpenCode v2 或 Grow 适配器。默认仍为静态审计；未声明模式的旧任务继续使用原契约，不会因升级扩大权限或自动重跑目标操作。

动态模式使用 `runtime-testing.v2`，只在新任务显式选择后生效。Planner 的工具只有提交规划，输入只有脱敏摘要；执行 Worker 接收完整私有环境说明，通过控制器的 Chrome DevTools MCP 或 SSH 执行器接触授权目标。页面、真实网络记录与静态报告都是不可信证据，不能改变执行权限。HTTP 请求／响应继续进入动态验证页面的动作详情和 Bruno／HAR 导出；没有捕获 HTTP 时只展示实际 Web 或 SSH 动作，不伪造可重放请求。

联合审计在静态报告接收事务内记录 `static.report.accepted`，以报告字节摘要、任务、尝试编号、发现摘要生成不可变 FindingRevision；报告更正产生新版本，旧版本只存档。控制器完成实验时记录 `runtime.packet.completed`；重复通知不会重复实验。工作包引用冻结源码任务或真实 RuntimeSurface，无静态发现时也可独立探索。

运行证据支持的线索进入单独的 `source-followup.v1` 源码补充轮次。该轮在初始静态交付和动态探索结束后启动，不重开初始任务板，不修改原文件／API／Focus Area 分母。最多一轮、六项任务，每项沿用任务面板的十分钟租约与有限失败重试。补充报告随原始报告和运行候选一起进入质量、正方、反方和裁决复核。部署版本未经验证时，运行结论保留 `UNKNOWN`，不能仅凭路径相似归因于源码。

当前自主探索限制为最多 8 轮规划、24 个实验，每轮最多 3 个意图、128 个范围；规划输入上限 6 万字符。全文证据仍存档，摘要截断明确记为未覆盖缺口。Planner 和 Worker 共用平台 Agent 并发配额，等待配额不计入主动测试耗时。自主探索暂不开放删除、重置、上传、批量写入和资源耗尽；通用页面点击仍需 Agent 遵守授权测试范围，不能宣称已经实现服务端对象级访问沙箱。

探索记录为 `reports/runtime-testing/<audit_id>/exploration.json`，独立源码补充为 `reports/source-followup/<audit_id>/round-1.json`。最终复核同时绑定运行证据、探索图与补充报告摘要。暂停、异常中断或清理状态未知时封存已有证据，不自动重放可能改变环境的操作；恢复可以继续证据复核，需要重新访问目标时通过新建重试重新确认授权。

## 原有执行与授权契约

以下环境说明、精确 origin 限制、身份隔离、清理与证据约束继续适用。历史 `runtime-testing.v1` 的逐 Focus Area 工作包仍按旧任务契约运行；v2 的实验由后台规划，主 Agent 不再手工 enqueue。
## 使用方式

在新建审计窗口启用“测试环境信息”，选择参与方式和允许的动作，直接用自然语言填写环境说明。整段内容作为私有 prompt 交给动态测试 Agent，不要求固定字段名、分行格式、账号数组或 JSON。系统不再用正则是否匹配来判断账号、密码或环境是否存在。

例如可填写：

```text
测试环境在 http://test.example:8080。
前端管理员账号密码：测试用户名/测试密码。
先登录前端，只操作指定的测试记录；结束后通过页面删除测试数据。
```

“测试身份偏好”默认由 Agent 根据说明判断。可描述多个测试账号、各自角色、SSO 或其他登录方式；是否需要密码由实际登录方式决定，不再强制凑齐 username/password 字段。真实凭据只写入私有环境说明，不在普通查询 API、日志或报告中回显。点击“新建重试”或“再次审计”时，专用接口校验原任务归属与私有文件摘要后回填两段原说明及开关；表单也保留原来的动态测试选项，提交前可以编辑。

未启用或内容为空时，控制器直接 SKIPPED，不启动 Agent、浏览器或目标请求。其他情况下，Agent 先完整理解原文，再登记用户提供的目标、实际身份和敏感值。工具目录发现不会提前启动 Chrome。原文确实不足以确定当前步骤需要的信息时，Agent 直接提交具体中文缺口，跳过对应工作，静态审计继续。

目标是否为授权测试环境由用户自行判断，不根据公网、内网或本机地址分类拒绝。Agent 登记执行配置后，控制器按协议、主机与端口精确约束浏览器访问，保持环境互斥和身份隔离。需要跨主机或端口登录、访问 API 或加载子资源时，在说明中写明这些授权地址即可，不要求手填 origins JSON。

允许创建测试记录时，在说明中写明测试数据范围和应用清理方法。Agent 理解后登记这些约束，不得自行补造范围或破坏性清理方法。缺少写入范围或清理说明只限制写入测试，不阻断正常访问和登录。工作包绑定不含原文的范围标识，实际说明只在私有上下文中传给执行 Agent。

原始 prompt 摘要与用户动作授权先冻结；首次 CONTACT 在连接目标前登记一次执行配置，并重新绑定该 CONTACT 的目标和身份。后续包复用配置和完整 prompt，不能更改目标或冒充其他身份。更新前已创建的任务不会因升级自动扩展授权；需要新规则时新建任务。旧版 quick 和人工补充验证继续按各自历史契约处理。

## 结果与预算

工作台任务详情展示 CONTACT、EXPLORE、CONFIRM、CLEANUP 的状态、每包结果、耗时与清理状态。执行成功并不代表漏洞成立；SUPPORTED 是工作包的观察标签，必须经过独立正方、反方与 Moderator 复核。

默认总预算 60 分钟，其中 10 分钟留给清理；单包通常 5–10 分钟。控制器计时包含模型等待和工具调用，排队不消耗主动预算。环境最大存续时间为总预算四倍且至少一小时。每假设最多两次测试，重试需要新增证据说明。耗尽预算的未执行包是 SKIPPED，真实超时才是 TIMED_OUT。

超时、取消在途测试、清理失败、未知环境状态或进程异常恢复会停止环境复用。已获得的证据仍保留，清理失败也不会自动抹去有效发现。静态报告继续完成，并列明测试残留与人工处理要求。

每个审计的证据保存在 `reports/runtime-testing/<audit_id>/`：授权摘要、状态、每包输入/结果、脱敏工具证据与封存 evidence-set。环境原文和 worker 附件放在受控私有状态目录，工作台普通查询 API 不返回凭证；专用重试回填接口只在用户点击时读取原说明，响应禁止缓存。多个审计共享的环境锁位于状态目录的 `runtime-environment-leases/`；异常退出遗留锁必须在确认本次浏览器、SSH 远端进程与测试数据已处理后由操作者移除，平台不会自动清锁并重连。

三方 intake、角色与 routing 使用 v3；最终模型也使用 v3。没有源码映射的中期候选仍接受三方复核，在报告中单列为 RUNTIME_ONLY、source_mapping=UNKNOWN；不会伪造源码位置、计入源码漏洞数量或直接套用源码 CVSS/攻击链。历史 v1/v2 制品仍按原契约读取。

## 运行与回归

在主机直接运行平台，禁止使用容器。Web 运行测试使用跨平台的 OpenCode、Node.js、Chrome 与项目固定版本的 Chrome DevTools MCP；macOS 不因操作系统被拒绝。winapp CLI 的 Windows 桌面控制限制仅作用于 Windows 专用功能。

环境自检按依赖和 MCP 配置判断 Web 动态验证是否可用。在 macOS 上检查系统和用户 Applications 目录的 Chrome，在 Windows 上检查安装目录；这些检查只读取可执行文件是否存在，不为读取版本而启动浏览器。依赖缺失时列出实际缺少项，不以主机 OS 代替能力检查。

没有需要清理的操作时，界面显示“无需清理”，不显示“清理已完成”。旧任务因 `RUNTIME_HOST_UNSUPPORTED` 或 `runtime-host-unsupported` 被跳过或启动受阻时，界面说明旧版限制已移除。原始证据状态保持不变；更新并重启工作台后，通过“新建重试”沿用原说明重新执行，不自动启动历史任务。

没有真实测试环境时，可以运行使用伪浏览器的回归；Web 运行测试入口不设 OS 门禁：

```sh
npm --prefix .opencode run test:runtime-testing
npm --prefix .opencode run test:truth-validation-contract
npm --prefix .opencode run test:stage-agent-contract
npm --prefix .opencode run test:stage-delivery-contract
npm --prefix .opencode run test:audit-workbench
npm --prefix .opencode run test:config
```

历史版本曾经授权在 macOS 上完成可移植回归：主测试入口的 23 个脚本组分别执行并全部通过。真实 Chrome DevTools 联调与 Windows/Linux 原生运行验收尚未执行。上线前仍需在实际部署主机复测，并用另行明确授权的测试环境验证实际登录隔离、浏览器代理拦截、应用证据与清理路径。详细历史范围及修正记录见 [macOS 回归验证记录](macos-regression-verification.md)。

历史运行测试的 31 个用例曾通过，覆盖缺少环境时零启动、新旧协议分流、身份隔离、默认 HTTPS 端口与 loopback 代理、初始化和队列取消竞态、预算与超时、清理失败保留证据、异常恢复、输入与证据归属绑定、不可用状态自动封存、XSS 应用证据要求以及 v3 报告收尾。这里的浏览器与 worker 使用替身；代理用例只启动用例自身的临时 loopback HTTP 服务，不连接被审计目标。

完整回归中的部分历史测试入口仍使用以下 macOS 可移植测试开关；它不决定 Web 功能是否能在 macOS 运行，也不放行 Windows 原生桌面工具。本次仍按用户要求仅静态检查，不运行这些命令：

```sh
AUDIT_ALLOW_MACOS_PORTABLE_TESTS=1 npm --prefix .opencode test
```

Agent 的命令与字段说明见 [运行测试执行契约](../.opencode/lib/runtime-testing/workflow.md)。人工验证入口继续生成独立 sidecar；补充环境、扩大授权或重新生成终稿通过新建审计保留版本，不覆盖既有结论。

## SSH 动态测试与报告验证

新版独立动态、联合审计及基于报告验证均使用 `runtime-testing.v2`，支持 Web、SSH 或同时登记两类访问通道。动态测试不以“有前端页面”作为前提。只有 SSH 登录方式时无需 HTTP(S) 地址，也不要求安装或启动 Chrome；环境自检单列 SSH 能力。旧 quick/manual 与 v1 浏览器契约不扩大，已结束任务保留历史结果，使用新能力须重新创建任务。

环境仍填写自然语言，例如：“授权通过 SSH 登录测试主机 test-host 的 2222 端口，使用所提供的测试账户和口令；仅测试 /srv/demo 下的程序和专用记录，禁止操作其他服务。”也支持用户明确提供的私钥正文或本机私钥绝对路径以及解密口令。Agent 完整理解后登记，不扫描密钥目录或代理补充凭据。可提供 `SHA256:…` 主机指纹；没有提供时记录并固定本任务首次连接的指纹。固定指纹不匹配时停止连接。

SSH 目标按主机、端口、身份登记并参与环境互斥。控制器提供 `ssh_connect` 和 `ssh_exec`，不开放宿主本机 shell、SSH 转发或 SFTP。SSH 登录证据可以完成 CONTACT，实际远端命令、标准输出、标准错误、退出码、指纹、超时和截断标记进入脱敏证据及动态动作详情，不伪造 HTTP 交换。用户的操作范围由执行 Agent 按私有环境原文遵守；SSH 传输绑定并不构成远端命令的操作系统沙箱，命令不得横向访问其他目标或读取无关数据。

单命令默认 30 秒、最长 40 秒，仍受工作包和总预算限制。不允许后台驻留规避预算。超时或中断后停止复用，清理状态保留 UNKNOWN，环境占用等待核对，因为关闭 SSH 通道不能证明远端子进程停止。正常命令非零退出保留实际结果，不自动推定漏洞或安全。SSH 管理员能够执行命令本身不是应用漏洞证明；报告候选仍须真实应用入口、影响和反证证据。

回归命令：`npm --prefix .opencode run test:runtime-ssh`。用例只连接测试自身创建的临时 loopback SSH 服务，通过固定测试响应验证 SSH 协议、认证、输出和生命周期，不登录业务主机，不执行真实远端 shell。
