运行侧

runtime-testing.v2 · 需授权环境

静态模式：动态验证为 SKIPPED。缺少授权或环境也会跳过。
1

理解环境并建立 CONTACT 基线

完整环境原文交给 Agent，登记受控身份、目标和允许动作。

2

规划 EXPLORE / CONFIRM

结合运行事实；联合模式还消费静态已接收报告，形成有限工作包。

3

通过 Web / SSH 执行

执行适配器限制目标与身份，记录操作、支持证据和反证。

4

清理并冻结运行证据

清理失败或远端状态未知如实保留，不抹去已形成的证据。

联合模式 · 一次独立源码补充

最多 6 条运行线索 → 独立补充任务板 → 冻结结果；不能定位时保留源码映射 UNKNOWN。

质量复核 → 正方 / 反方 / Moderator → 中文报告

源码与运行候选统一进入独立复核，报告分列确认漏洞、运行环境结论、反证和剩余缺口。

报告或单漏洞定向验证从已封存候选开始，只执行本次授权的确认路径。旧 quick/manual 流程按其版本合同保留。
