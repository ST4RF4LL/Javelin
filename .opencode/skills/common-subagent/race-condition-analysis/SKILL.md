# 竞态条件审计

只分析当前任务范围内的源码。先读取入口、共享状态和敏感副作用，再决定是否存在并发问题；关键词只是定位线索。不新增 Agent、全项目扫描或独立长篇报告，不运行目标程序、不发送并发请求。`discovery_track=blind` 的独立发现阶段不加载本技能；先保存源码事实，交由后续非盲审复核。仅关闭历史记忆不等于该发现轨道。

## 何时使用

- 同一资源可能被两个请求、线程、进程、队列消费者或异步回调读写：余额、库存、优惠、配额、唯一记录、任务状态、缓存、文件或共享对象。
- 检查与使用分离：权限检查后资源/身份变化、文件检查后路径替换、审批通过后参数改变、验证后消费令牌。
- 多步业务转换或重试存在窗口：检查剩余额度后扣减、查重后插入、核验后提现、取消与完成、重复回调、租约到期后的旧持有者写入。
- 同一操作并发执行与不同操作相互交错都要考虑，但只围绕当前共享资源及约束定点追踪，不枚举全系统接口两两组合。

## 分析顺序

1. **确定安全约束和攻击者能力。** 用一句话写业务不变量，例如“同一审批只能授权一次固定操作”或“成功扣减后的库存不能为负”。说明谁能同时触发哪些入口、需要何种权限、能够控制什么输入。普通竞争、性能问题或一致性延迟不能自动当成安全漏洞。
2. **确定真正共享的资源。** 记录表/行键、唯一键、缓存键、文件路径/句柄或对象身份。区分请求私有变量与跨请求状态；区分进程内、跨进程和多副本。沿调用链定点查看关联操作、迁移/约束及配置，不把变量同名当成同一资源。
3. **列出操作 A/B 的源码事实。** 每个操作标明入口与 read → check → write/side effect → commit 的实际文件行号、事务边界、锁获取/释放、异常和重试路径。A/B 可以是同一入口的两次调用；也可以是不同接口、后台任务或文件替换操作。未知数据库/第三方实现保留缺口。
4. **构造可行交错。** 例如 A 检查 → B 检查 → A 消费并提交 → B 消费并提交；逐步写出共享状态和约束破坏。核对锁、唯一约束、原子语句或运行模型是否禁止该顺序。源码中的 `await`、事务或无锁写入本身都不能证明交错可达；数据库冲突/回滚之后是否仍留下外部副作用也要追踪。
5. **主动寻找反证。** 检查下面的防护层及实际作用范围，并按需要读取 [语言与存储控制](references/language-controls.md)。无证据的控制为 UNKNOWN，不按不存在处理。
   - 原子条件更新/比较交换是否把检查和修改合在一次操作；是否核对影响行数/版本结果。
   - 唯一约束是否覆盖真实业务键；冲突后是否回滚、提前发出副作用或自动重试。
   - 行锁/互斥锁是否覆盖完整临界区、同一资源和所有入口；跨进程是否共用同一锁。锁住不存在的行、不同锁键或只锁提交后的逻辑不能凭名称认定安全。
   - 隔离级别是否来自实际配置；读取、提交冲突和重试语义能否维持该业务约束。事务存在不等于业务不变量自动成立。
   - 幂等键是否绑定身份、资源和操作内容，是否原子占用，是否在失效/错误重试后重复消费；分布式租约是否有 fencing/version 校验阻止旧持有者继续写入。
   - 权限、审批、令牌或文件对象在最终使用点是否重新绑定并验证；异步副作用与状态提交的先后关系是否留下窗口。
6. **给出有边界的候选。** 只有源码支持攻击者可达的交错、约束破坏与安全影响，且没有已证实的阻断控制时，才提交静态候选。阻断控制成立则记录反证，不提交该竞态；关键前提未知则保留 HYPOTHESIS/INCONCLUSIVE 或报告 gaps。严重性依据影响、权限和成立前提判断，不按某个 API 组合固定定级。顺序重复请求已经成立、无需任何交错的重放/幂等问题单独描述，不伪称 race。

## 交付

沿用宿主协议的 finding、evidence、guards、uncertainty、report_details 和报告 gaps，不引入必填字段或更改现有收据。至少交代：**业务不变量、共享资源、A/B 源码位置、可行交错、已查防护/反证、影响、未知前提及修复建议**。需要分段笔记时写到当前 output_root，以现有 evidence_refs 引用；不能把私有笔记留作结论的唯一依据。

业务竞态在适用的应用目录下沿用 `JW-BUSINESS-02`，并明确 race/TOCTOU 子类；该目录项同时包含非并发的重放与状态机问题，不能将它们全部改标为竞态。AI 专项保留当前选定风险族及其 `AI-*` 分类，竞态作为对应越权/审批/工具执行问题的机制，不添加未绑定的目录项。C/C++ 的数据竞争、内存生命周期或文件权限问题使用现有对应分类，按事实标注 CWE-362/CWE-367 等，不伪造目录 ID。

复现部分写静态推演与 `NOT_RUN`，不得生成“已发送请求/已证实”记录。获授权的运行控制器将来可以接收验证设计；请求制品不是执行许可，本技能不改变运行授权。修复应恢复不变量，例如带谓词的原子更新并检查结果、正确业务唯一键、完整事务及冲突重试、最终使用点绑定、锁范围或 fencing；同时设计正常单请求、合法并行、重复/交错和失败回滚的回归用例。

## 简短判别示例

- `SELECT remaining` 后在两次请求里均通过检查，再各自执行无下限谓词的扣减：需追踪真实事务/锁/约束及提交结果，才能支持“重复消费”的候选。
- `UPDATE quota SET remaining=remaining-1 WHERE id=? AND remaining>0`，且只有影响一行才允许副作用：该路径可能阻断超额消费；仍核对存储语义、关联入口和副作用次序，不能因没有显式 mutex 判漏洞。
- 只有前端按钮防重点击：这是线索；服务端幂等/唯一约束不可见时记录缺口，不能声称后端存在竞态。
